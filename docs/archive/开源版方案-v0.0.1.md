# 开源版方案 v0.0.1 · 从「自用脚本」到「可交付产品」

> ⚠️ 本方案范围过大，已被 [桌面控制台方案-v0.0.1.md](./桌面控制台方案-v0.0.1.md) 取代，仅作存档。

> 现状：单人自用、配置写死在 `config.yaml`、只有命令行和 Telegram。
> 目标：开源、带 Web 管理台、用户可自己接入模型、自己配置功能、打包成 exe。

---

## 0. 先把三件事说清楚

**① 这是一次产品化重构，不是加个页面。**
现在的代码是"一个翻译流程 + 一个 Telegram 壳"。加了管理台之后，配置要能热更新、模型要能增删、功能要能开关、多用户要能隔离——数据从 `config.yaml` 迁到数据库，是必做项，不是可选项。

**② 开源的第一件事是清理密钥，不是写 README。**
现在 `config.yaml` 里有你真实的 Bot Token 和 DeepSeek Key，`data/bot.db` 里有你的聊天记录。开源前必须：
- 去 BotFather `/revoke` 换新 Token；
- 去 DeepSeek 后台**删除并重建** API Key；
- `config.yaml`、`data/`、`logs/` 全部进 `.gitignore`，仓库里只留 `config.example.yaml`；
- 用 `gitleaks` / `trufflehog` 扫一遍历史提交（如果先提交再删，历史里还在）。

**③ "让用户设计机器人功能" 有歧义，必须先定边界。**
见第 2 节。这一条定义不清，工期能差 5 倍。

## 1. 0.0.1 的功能边界

### 要做（0.0.1 的验收标准）

| 模块 | 内容 |
|---|---|
| 安装向导 | 首次启动：选语言 → 填 Bot Token → 加模型 → 测试连通 → 完成 |

| 提示词编辑器 | 系统提示词可视化编辑，带变量说明、恢复默认、**页面内直接试译** |

| 开源 | MIT、README（中/英）、CHANGELOG、CI 自动构建 release |

- 云端部署托管
- 模型微调
- macOS / Linux 的 exe（源码可跑，打包只做 Windows）

## 2. "自己设计功能" 到底做到哪一层

这是最容易失控的地方。我把它拆成三层，**0.0.1 只做 L1 + L2 的一半**。

| 层级 | 用户能做什么 | 实现难度 | 0.0.1 |
|---|---|---|---|
| **L1 配置层** | 开关功能、改提示词、改语气、加术语、改按钮、设触发方式 | 低（本质是表单 + 数据库） | ✅ 全做 |
| **L2 技能层** | 自定义指令：`/摘要` + 提示词 + 选模型，输出到聊天 | 中（一张表 + 一个通用处理器） | ✅ 做简单版 |
| **L3 编排层** | 拖拽节点：收到消息 → 判断语言 → 调模型 A → 若失败调 B → 格式化 → 发送 | 极高（要做 DAG 引擎、变量系统、调试器） | ❌ 不做 |

**为什么不做 L3**：n8n 那种编排器是几十人年的工程。个人开源项目做这个，最后一定是"半成品 + 无数 issue"。L2 的技能模板能覆盖 80% 的"我想让它多做一件事"的需求，成本只有 5%。

L1 的"设计感"来自**即时反馈**：改完提示词，右边直接输入一句韩语点"试译"，立刻看到效果，不用重启、不用发 Telegram。这个体验比任何编排器都实用。

## 3. 可视化页面设计

8 个页面，本地打开 `http://127.0.0.1:8787`。

```
┌─────────────┬──────────────────────────────────────────┐
│ 侧边栏       │  主区域                                   │
│             │                                          │
│ ▸ 仪表盘     │  卡片：Bot 状态 / 今日调用 / 费用 / 错误    │
│ ▸ 模型       │  表格 + 新增 + 测试连接 + 拖拽排序         │
│ ▸ 翻译       │  表单 + 试译面板（左改右看）               │
│ ▸ 交互       │  触发方式 / 按钮 / 消息模板                │
│ ▸ 提示词     │  代码编辑器 + 变量提示 + 试译              │
│ ▸ 术语表     │  搜索 / 增删 / CSV 导入导出               │
│ ▸ 技能       │  /命令 + 提示词 + 模型                    │
│ ▸ 日志       │  过滤 + 导出诊断包                        │
└─────────────┴──────────────────────────────────────────┘
```

### 三个关键交互

**1. 模型测试**：填完 `base_url` + `key`，点"测试"，后端真的发一次 `GET /models` 和一次最小 `chat`，返回延迟和可用模型，失败给出中文原因（401/402/超时/证书）。

**2. 试译面板**：提示词页面右侧固定一个输入框，输入韩语 → 调当前配置 → 显示译文、耗时、token。改一行提示词，点一下就能看出差别。**这是整个 UI 最值钱的功能。**

**3. 向导式首次启动**：不让用户面对 8 个空页面。先只问三件事：语言、Bot Token、模型。填完直接跳"发一句测试"，通了再进主界面。

### 视觉

- 单页应用，浅色为主，跟随系统深色
- 不引前端构建链（没有 Node/npm），用 FastAPI + Jinja2 + HTMX + 预编译 Tailwind 单文件
- 所有资源本地化，离线可用——exe 里不能依赖 CDN

## 4. 架构调整

### 现在的结构（够个人用）

```
config.yaml → 进程启动时读一次 → 组件装配 → 运行
```

### 目标结构（够产品用）

```
SQLite（唯一事实来源）
   ├─ providers   模型（加密存 key）
   ├─ settings    全局配置
   ├─ tones       语气方案
   ├─ glossary    术语表
   ├─ skills      自定义指令
   ├─ usage       调用记录
   └─ cache / pending

Runtime（内存快照）
   ├─ 加载全部配置
   ├─ 构建 Provider / Translator / Bot
   └─ save() 时原子重建，无需重启

Web API (FastAPI)  ──写──▶  DB ──▶ Runtime.reload()
Telegram Bot       ──读──▶  Runtime
```

关键点：

1. **`config.yaml` 降级**为启动参数（端口、数据目录、日志级别），只管"怎么跑"，不管"跑什么"。
2. **配置热更新**：页面上点保存 → 写库 → 重建 Runtime → 下一次消息立即生效。不重启是产品级体验的分水岭。
3. **密钥加密**：`api_key` 用 Fernet 加密存库，密钥文件放数据目录（首次生成）。页面上永远只显示 `sk-****abcd`。
4. **单进程双协程**：uvicorn 和 aiogram 跑在同一个 asyncio loop 里，exe 启动一个进程即可。省内存，也好排障。

### 目录（开源仓库形态）

```
translator-bot/
├─ app/
│  ├─ core/          翻译引擎（不依赖 Telegram / Web）
│  ├─ providers/     模型适配（openai 兼容 + 注册表）
│  ├─ storage/       SQLite + 仓储 + 迁移
│  ├─ bot/           Telegram 层
│  ├─ web/           FastAPI 路由 + 模板 + 静态资源
│  ├─ runtime.py     配置快照与热加载
│  └─ main.py        入口（bot / web / 双开）
├─ tests/            pytest：翻译管线、provider、API
├─ packaging/        PyInstaller spec、图标、构建脚本
├─ docs/             截图、FAQ、配置说明
├─ .github/workflows 打 tag 自动出 exe
├─ config.example.yaml
├─ LICENSE (MIT)
├─ README.md / README.en.md
└─ CHANGELOG.md
```

## 5. 技术选型（增量部分）

| 需求 | 选型 | 理由 |
|---|---|---|
| Web 框架 | FastAPI + uvicorn | 异步、和 aiogram 同 loop、自带 OpenAPI |
| 模板 | Jinja2 + HTMX | 无构建链，exe 里省事 |
| 样式 | Tailwind 预编译单文件 | 不装 Node，离线可用 |
| 加密 | `cryptography` Fernet | 跨平台，标准做法 |
| 打包 | PyInstaller `--onedir` | 启动快、比 onefile 少被杀软误杀 |
| 测试 | pytest + pytest-asyncio | 常规 |

新增依赖约 4 个（fastapi、uvicorn、jinja2、cryptography），打包体积 +15MB 左右。

## 6. exe 打包方案

- **形态**：`onedir`（一个文件夹 + `翻译机器人.exe`），不是单文件。单文件每次启动要解压到临时目录，慢 3~5 秒，还更容易被 Defender 误杀。
- **启动流程**：双击 → 单实例检查 → 起 uvicorn（127.0.0.1:8787）→ 起 Telegram 轮询 → 自动打开浏览器 → 托盘图标（可选）。
- **数据目录**：默认 `%APPDATA%\KoreanTranslatorBot\`；如果 exe 同目录有 `portable.txt`，则用同目录 `data/`（绿色版）。
- **失败兜底**：端口占用→随机换端口；启动异常→弹原生对话框并给出日志路径；提供 `诊断模式.bat`（带控制台窗口）。
- **体积预估**：45~60MB。
- **签名**：不做代码签名（证书要钱），README 里说明 SmartScreen 提示怎么处理。

## 8. 迁移路径（不影响你现在用）

1. 先从现有 `config.yaml` + `bot.db` **导入**到新库：生成 providers 记录、迁移 owner、术语表、缓存；
2. 旧的 `bot.db` 备份一份，不删；
3. 新版本首次启动检测到旧数据 → 提示"已从旧配置迁移"，可回滚；
4. 你的日常使用不受影响：迁移后 Telegram 那边照常发消息。

## 10. 风险

| 风险 | 影响 | 应对 |
|---|---|---|
| "设计功能"被理解成流程编排 | 工期 ×3 且大概率烂尾 | 本方案已明确划到 L2，写进 README |
| PyInstaller 打包异步栈踩坑 | 打包出来的 exe 起不来 | M5 单独留 2 天，先做最小可运行验证 |
| 杀软误报 | 用户不敢用 | 提供源码运行方式 + 说明文档 |
| 开源后 issue 洪水 | 精力被拖垮 | 模板化 issue、文档先行、明确 Not planned |
| 密钥泄漏 | 直接经济损失 | 提交前扫描 + 轮换 |
