# 桌面控制台方案 v0.0.1（收窄版）

> 一句话：**不重构，只加一层壳。** 现有翻译逻辑、配置、守护进程全部保留，新增一个桌面窗口用来配置模型和功能开关，最后打包成 exe。

---

## 1. 和上一版方案的区别

| 项 | 上一版（产品化） | 本版（收窄） |
|---|---|---|
| 配置存储 | 迁到 SQLite | **保持 config.yaml**，UI 只是编辑器 |
| 热加载 | 重写 Runtime | **保存后重启进程**，够用 |
| 页面 | 8 个页面 + 首次向导 | **4 个页签** |
| 技能/编排 | L1 + L2 | **只做 L1：功能开关** |
| 多用户/权限 | 有 | **无**（本机单人） |
| 工期 | 15 天 | **4~5 天** |
| 开源 | 完整仓库工程 | 顺手带上 LICENSE + README，不做 CI |

**核心思路**：机器人还是现在这个机器人，UI 只负责"读写配置文件 + 控制进程"。改动集中在三层：`config.yaml` 加 `features` 段、handler 里判断开关、新增一个窗口程序。

## 2. 窗口长什么样

一个原生窗口（不是浏览器标签页），左侧四个页签：

```
┌──────────────────────────────────────────────┐
│  韩语翻译机器人 0.0.1          ● 运行中       │
├────────────┬─────────────────────────────────┤
│ 概览        │  今日 12 次 · 3,240 token · ¥0.02│
│ 模型        │  [启动] [停止] [重启]            │
│ 功能        │  最近错误：无                    │
│ 日志        │  最近 20 条日志…                 │
└────────────┴─────────────────────────────────┘
```

### 页签 1 · 概览
- Bot 状态（运行中 / 已停止）、当前模型、今日调用次数、token、估算费用
- 启动 / 停止 / 重启三个按钮
- 最近 20 条日志滚动显示
- 开机自启开关

### 页签 2 · 模型
- 列表：名称、接口地址、Key（显示 `sk-****abcd`）、模型名、是否默认
- 新增 / 编辑 / 删除 / **测试连接**（真的发一次请求，返回延迟或中文错误）
- 可加多个，选一个默认；可设兜底顺序

### 页签 3 · 功能
勾选框，每个都真正生效（不是装饰）：

| 开关 | 作用 | 默认 |
|---|---|---|
| 双语对照 | 译文上方显示原文 | 开 |
| 语气按钮 | 显示 `更正式 / 更口语 / 直译` | 开 |
| 解释按钮 | 显示 `解释一下`（仅韩语） | 开 |
| 术语表 | 启用 `/glossary` 命令 | 开 |
| 上下文 | 带最近 N 条原文，改善指代 | 开 |
| 缓存 | 重复内容不重复计费 | 开 |
| 自动识别方向 | 韩→中 / 中→韩 自动判断 | 开 |
| 群聊响应 | 全部 / 仅 @ / 仅回复 | 仅回复或@ |
| 单次字数上限 | 超过则提示分段 | 6000 |

下面折叠一个「高级」区：系统提示词、语气描述，可编辑、可恢复默认。

### 页签 4 · 日志
- 最近 200 条，按级别过滤
- 一键导出诊断包（自动脱敏 Key 和 Token）
- 打开日志文件夹

## 3. 配置文件怎么变

`config.yaml` 保持人类可读，只加两段：

```yaml
models:
  - name: DeepSeek V4 Pro
    base_url: https://api.deepseek.com/v1
    api_key: sk-xxx
    model: deepseek-v4-pro
    kind: text
    default: true

features:
  bilingual: true
  tone_buttons: true
  explain_button: true
  glossary: true
  context: true
  cache: true
  auto_detect: true
  group_mode: reply_or_mention
  max_input_chars: 6000
```

旧的 `llm:` 段继续兼容（首次打开 UI 时自动迁移成 `models` 列表，并备份原文件）。

## 4. 技术做法

| 部分 | 选型 | 说明 |
|---|---|---|
| 窗口 | **pywebview**（Edge WebView2） | Win10/11 自带 WebView2，不额外装运行库；窗口是原生的，不是浏览器 |
| 前后端通信 | pywebview 的 JS 桥（`window.expose`） | **不起 HTTP 服务、不占端口**，没有网络面，不用做登录和 CSRF |
| 界面 | 单个 HTML + 少量原生 JS | 不引入前端框架和构建链，打包简单 |
| 配置读写 | Python 直接改 `config.yaml` | 保存前校验，写前自动备份 `config.yaml.bak` |
| 机器人进程 | 由控制台以子进程方式启动 | 复用现有 `app.main`，停止/重启就是结束/拉起子进程 |
| 打包 | PyInstaller `--onedir` | 一个文件夹 + exe，启动快，比单文件少被杀软误杀 |

**关键点**：不起 Web 服务，就没有"端口被占用""别人能访问我的配置"这类问题。窗口关了就没了。如果目标机器缺 WebView2，自动回退成用默认浏览器打开同一个页面。

## 5. 运行方式

```
翻译机器人.exe
 ├─ 双击 → 打开控制台窗口（同时按需拉起机器人）
 ├─ 关窗口 → 询问：最小化到托盘 / 退出并停止机器人
 └─ 翻译机器人.exe --headless → 不开窗口，只跑机器人（兼容现在的开机自启）
```

托盘菜单：显示窗口 / 重启机器人 / 退出。开机自启沿用现有的启动文件夹方式，只是目标从 `pythonw` 换成 exe。

## 10. 增量需求：多语言（0.0.1 核心变化）

从"韩中互译"升级为"多语种互译"，语言池定为 14 种主流语言：

| 代码 | 语言 | 识别方式 |
|---|---|---|
| zh | 中文 | 汉字 |
| ko | 韩语 | 谚文 |
| ja | 日语 | 假名 |
| en | 英语 | 拉丁字母 + langdetect |
| es / fr / de / pt / it / ru / id / vi / th / ar | 西/法/德/葡/意/俄/印尼/越/泰/阿 | 文字系统 + langdetect |

### 工作机制（不做"每次问用户译成什么"）

```
用户设定：我的语言 = 中文，对方语言 = [韩语, 日语, 英语]

收到消息 → 检测语种
  ├─ 是对方语言 → 译成「我的语言」
  ├─ 是我的语言 → 译成「最近一次对话的对方语言」（默认列表第一个）
  └─ 都不是     → 译成「我的语言」，并在卡片上标注检测结果
```

- 中文/韩语/日语/泰语/俄语/阿拉伯语靠文字系统直接判定，准确率 100%
- 英语/西语/法语/德语等拉丁语系，用 `langdetect` 判定，置信度低于阈值时按「我的语言」处理
- `/lang ko` 可临时锁定方向，不用改配置
- 卡片上永远标注 `检测为 韩语 → 中文`，判断错了用户一眼能看出来，点一下就能改

### 连带改动

| 模块 | 改动 |
|---|---|
| 提示词 | 按语向动态生成，不再写死"韩中互译" |
| 术语表 | 增加 `语言对` 字段（예: ko→zh 的 김치=泡菜，en→zh 的 김치=kimchi） |
| 上下文 | 按会话+语言对隔离，避免串味 |
| UI | 新增「语言」页签：我的语言、对方语言多选、"检测不准时默认译成" |
| 按钮 | 「解释一下」改为「讲解原文」，只对"非我的语言"出现 |

工作量 +1.5 天，总工期 6 天左右。

## 11. 增量需求：托盘与图标

### 图标设计

- **造型**：圆角方形底 + 一枚对话气泡 + 气泡内双向箭头（⇄）
- **配色**：靛蓝 `#4F46E5` → 紫 `#7C3AED` → 天青 `#0EA5E9` 的对角渐变，白色气泡
- **理由**：气泡 = 聊天，双箭头 = 互译；几何造型在 16px 下仍可辨认，不依赖文字，避免多语言歧义
- 输出：`icon.ico`（16/32/48/64/128/256 六种尺寸）+ `icon.png`（512）
- 托盘图标用同一套，深色/浅色任务栏都能看清

### 托盘行为

- 关闭窗口 → 收进托盘，机器人继续跑，弹一条气泡提示"仍在后台运行"
- 托盘菜单：显示主界面 / 重启机器人 / 打开日志 / 退出
- 双击托盘图标 → 显示窗口

## 13. 增量需求：自动更新

0.0.1 就要能"程序内完成更新"，方案：

```
启动时（每天一次）→ GET api.github.com/repos/<owner>/<repo>/releases/latest
  ├─ 版本相同 → 什么都不做
  └─ 有新版本 → 概览页出现横幅："发现 0.0.2，查看更新"

点"更新" → 下载 release 里的 zip
        → 校验 sha256（release 里附带 checksums.txt）
        → 解压到 data/update/<version>/
        → 启动 updater.exe（独立小程序）
             ├─ 等待主程序退出
             ├─ 备份旧目录 → 替换文件
             ├─ 失败则回滚
             └─ 重启主程序
```

- onedir 形态无法"边跑边替换自己"，所以必须有一个 updater 小程序，这是标准做法
- 校验失败或断网 → 中止并提示，不动现有文件
- 也可以"跳过这个版本"，记录在配置里

工作量 +1 天。

## 14. 视觉方向（"不像普通工具"）

| 维度 | 方案 |
|---|---|
| 基调 | 深色为主（`#0B0F1A`），可切浅色 |
| 主色 | 靛蓝→紫渐变，强调色天青 |
| 层次 | 卡片 12px 圆角、1px 半透明描边、柔和外阴影，不用重边框 |
| 字体 | 系统字体栈（Segoe UI Variable / PingFang / Noto），标题 600、正文 400，行高 1.6 |
| 动效 | 页签切换 150ms 淡入+位移；按钮 hover 有 1px 上浮；保存成功右下角 toast |
| 细节 | 空状态有插画位；加载用骨架屏不用转圈；表格行 hover 高亮；快捷键 Ctrl+S 保存 |
| 纪律 | 不堆渐变和阴影，克制才显高级；一屏只保留一个主按钮 |
